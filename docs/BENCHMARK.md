## Notes and caveats

* **Clean serial re-check.** 34 legs from 4 layouts (A_spread_05, B_clutter_04, D_seeded_04_s2, E_ordering_04_c1) were re-timed with nothing else running and the C++ minimum taken over 5 runs: overall **33.2x**, median 32.6x (range 30.3x to 36.8x), so contention from the parallel main run did not inflate the speed-up.
* **Two legs differ by one A* expansion.** In B_clutter_06 leg 11 and D_seeded_04_s1 leg 4 the expansion count differs by exactly 1 (33675 vs 33676, 26615 vs 26616) while the commands, cost and final pose are identical. A likely cause (not proven for these two legs) is that CPython's `math.hypot` is not libm's `hypot`: on 20000 random pairs the two differ in the last bit about 16 % of the time, which can reorder a near-tie in the open list.
* **Failing legs.** 57 of the 327 legs are infeasible by construction (a fixture with no safe viewing pose, or an unsafe start); both planners reject them for the same reason.
* **Route-level scope.** Only layouts with up to 4 obstacles were compared against Python's exhaustive B3 search (it enumerates every order, so 4 obstacles already take 6 to 11 minutes in Python). For 6 to 8 obstacles the C++ search normally reaches its 70 s wall-clock limit and returns the best *verified* complete route found so far, which is not proven optimal; that case has not been compared against Python's bounded prefix-tree executor.
* **6 to 8 obstacles, C++ only (idle machine, 70 s limit).** A_spread_06/07/08 and B_clutter_06 each ran to the 70 s limit and returned a complete, verified route (375, 329, 567 and 370 legs planned); none is proven optimal. D_seeded_08_s1 has no safe viewing pose under the live geometry and failed immediately with `no_safe_viewing_pose`.
* **Not measured:** memory use, anything on the physical robot, planners other than the ones above.

## Environment

* Machine: Windows-10-10.0.26200-SP0, Intel64 Family 6 Model 186 Stepping 3, GenuineIntel
* Python: 3.11.5 (reference planner, unmodified)
* C++: g++ (Rev6, Built by MSYS2 project) 13.1.0, Release build (`-O3 -DNDEBUG`), `-ffp-contract=off`
* Both planners run single-threaded, one leg at a time, from the same exact poses and obstacles.
* Main run: six single-threaded comparison processes ran in parallel on a 12-thread desktop (plus normal desktop load); C++ time per leg is the minimum of 3 runs, Python time is a single run.
